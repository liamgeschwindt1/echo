## Reading

- Optimisation applied (supported by the before-profile, where ~90 % of Create was GCC-PHAT): `estimateBearing` now packs the four mics into two complex FFTs and evaluates the band-limited PHAT correlation only at the needed lags. Bearings agree with the old code to 1.3e-10 degrees (golden tests).
- Acceptance: scene 3 at order 2 takes 96.6 s against 52.7 to 57.4 s before (budget: 2x the before time, about 105 to 115 s). Met, narrowly. The remaining hot spot is the per-microphone render (78 s on scene 3: 42 paths per source and mic on average, each looping over 1 M bins). The short-buffer, decimated-localisation and skip-bins optimisations were NOT implemented.
- Heatmap timings are in the last section.
- Single run, noisy; the "before" scene 3 ran at diffraction order 0 as specified.

## Heatmap field timings (`node scripts/sim-heatmap-timing.mjs`)

Time to compute the per-cell arrival tables (top 16 arrivals per cell, diffraction order 2, reflection order 2) plus the clip band envelopes, in Node on one thread. The sensitivity sweep was running at the same time, so these are upper bounds. In the app this runs in a worker, shows a 4 m preview first and then the configured 2 m cell size. The default heatmap shows the selected source only, so scene 3 with one selected source costs about a quarter of the "4 sources" rows (all-sources option).
